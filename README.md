# Расчёт для инвестора

Сайт из трёх частей, как в вашей таблице «Расчёт для Вити»:

1. **Расчёт за месяц** — загружаете отчёты WB, Яндекс Маркета и Ozon (можно все сразу), получаете расчёт по товарам (выручка, средняя прибыль на единицу, фулфилмент, ФОТ, чистая прибыль). Кнопки «Создать расчёт» и «Пересчитать».
2. **Товар инвестора** — деньги в товаре (на складе и в пути), закупки, потеря товара, корректировки себестоимости.
3. **Движение денег** — таблица как в Excel: месяцы в столбцах, статьи в строках. Входящий остаток, проданный товар, чистая прибыль, сгоревший товар, новые закупки, корректировки и накопленная чистая прибыль подтягиваются сами. Вручную вводятся только внесение и вывод средств (это может делать и инвестор).

Четвёртая вкладка, **Справочник**, хранит соответствие «артикул WB → товар инвестора» и стартовые параметры.

## Как это устроено

* Сайт — обычные статические файлы, лежат на GitHub Pages.
* Данные — JSON-файлы в **отдельном приватном репозитории**. Сайт читает и пишет их через GitHub API с помощью токена.
* Отчёты читаются в браузере (читаются только нужные листы, поэтому большие файлы по 5–9 МБ открываются быстро). В базу попадают только строки по артикулам (продажи, цена, прибыль на единицу) и суммы расходов, сами файлы не загружаются.
* Поддерживаются три вида отчётов: WB (листы «По артикулам» и «ОПиУ - месяцы»), Яндекс Маркет («По Артикулам» и «ОПиУ - месяцы») и Ozon («Артикулы» и «ОПиУ»). Кабинет определяется по полю «Юрлицо» на листе «Информационный лист».

Файлы в репозитории с данными:

| Файл | Что хранит |
|---|---|
| `settings.json` | справочник артикулов, входящее сальдо первого месяца, проценты по умолчанию |
| `ledger.json` | закупки (партии), потери, корректировки |
| `flows.json` | внесение и вывод средств по месяцам (его правит и инвестор) |
| `months/ГГГГ-ММ.json` | данные отчётов за месяц (по каждому кабинету) и снимок итогов |

## Установка по шагам

### 1. Репозиторий для сайта

1. На github.com нажмите **New repository**, назовите, например, `report_invest`, выберите **Public**.
2. Загрузите в него все файлы из этой папки (**Add file → Upload files**): `index.html`, `README.md` и папки `js` и `css`.
3. **Settings → Pages → Build and deployment**: Source = *Deploy from a branch*, Branch = `main`, папка `/ (root)` → **Save**.
4. Через минуту-две сайт откроется по адресу `https://ВАШ-ЛОГИН.github.io/report_invest/`.

Публичный репозиторий нужен потому, что Pages для приватных репозиториев доступны только на платных тарифах. В нём нет никаких данных, только код. Без токена сайт показывает пустой интерфейс.

### 2. Репозиторий для данных

1. **New repository**, имя, например, `investor-data`, выберите **Private**.
2. Поставьте галочку **Add a README file**, иначе в репозитории не появится ветка `main`.

### 3. Токен доступа

1. GitHub → ваш аватар → **Settings → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. Название, например `investor-site`; срок действия — на ваше усмотрение (можно год).
3. **Repository access → Only select repositories** → выберите `investor-data`.
4. **Permissions → Repository permissions → Contents: Read and write**.
5. **Generate token** и скопируйте его сразу, потом GitHub его не покажет.

Для инвестора создайте **второй токен** тем же способом, чтобы его можно было отозвать отдельно, и передайте ему лично.

### 4. Подключение сайта

1. Откройте сайт → **Подключение**.
2. Выберите *GitHub*, укажите логин владельца, `investor-data`, ветку `main`, вставьте токен, выберите роль (вы — «Владелец», инвестор — «Инвестор»).
3. Нажмите **Проверить**, затем **Сохранить**. Подключение настраивается отдельно на каждом устройстве.

### 5. Первый запуск

1. **Справочник**: проверьте, какой артикул WB относится к какому вашему товару, при необходимости поправьте и сохраните. Заполните «Входящее сальдо первого месяца» (остаток на начало учёта на сайте).
2. **Товар инвестора**: внесите закупки (товар, себестоимость, количество, месяц, статус).
3. Нажмите **Создать расчёт**, выберите месяц и перетащите файлы отчётов всех кабинетов.
4. На вкладке «Справочник» сопоставьте оставшиеся артикулы с вашими товарами (список «без привязки» показывает артикулы с продажами и маркетплейс). Затем в нужном месяце нажмите «Пересчитать».

## Стартовые данные (начало учёта)

1. **Справочник → Параметры**: «Входящее сальдо первого месяца» — деньги инвестора на конец месяца перед первым расчётом (например, на 31.08.2026, если первый расчёт — сентябрь) и «Прибыль накопленным итогом до первого месяца» — историческая накопленная прибыль на ту же дату.
2. **Товар инвестора → Новая закупка**: для каждого товара, который уже есть на складе или в пути, добавьте строку с галочкой «Начальный остаток», месяц 08.2026, себестоимостью и количеством. Деньги за такие партии не списываются (они уже учтены в сальдо), а остаток попадает в «Деньги в товаре» и дальше списывается продажами.
3. Товар «в пути» переводится «на склад» в таблице «Деньги в товаре» (выпадающий список «Статус» в строке партии, только у владельца).

## Порядок работы каждый месяц

1. В каждом отчёте на листе «По артикулам» (у Ozon «Артикулы») задайте недели месяца (неделя относится к месяцу, если в нём хотя бы 4 её дня).
2. **Создать расчёт** → выберите месяц → перетащите все файлы. Новый файл того же кабинета заменяет прежний, остальные остаются; так можно добавлять кабинеты по одному.
3. Если были новые закупки, потери или изменилась себестоимость — внесите на вкладке «Товар инвестора».
4. Инвестор отмечает внесение и вывод средств на вкладке «Движение денег».
5. Проверьте исходящее сальдо и прибыль накопленным итогом.

## Как считается

* **Продано** = доля инвестора (по умолчанию **1/3**) от органических продаж по всем отчётам, округлено вверх. Долю можно изменить в «Справочнике» и отдельно для месяца при пересчёте.
* **Цена** и **прибыль на единицу** — **средние** по всем кабинетам и маркетплейсам: Σ(значение × продажи) ÷ Σ продажи (учитываются артикулы с положительными продажами). Берутся «средний чек / цена продажи до СПП» и «операционная прибыль на единицу». Как получилась каждая средняя, видно в блоке «Как получены средние цена и прибыль на единицу».
* Продажи учитываются **только по товарам, которые есть у инвестора на складе** (с учётом начальных остатков и закупок «на складе»). Если товара нет в наличии или он только «в пути», его продажи за месяц не считаются, а на странице месяца показано предупреждение. Продано не может быть больше остатка на складе: избыток отсекается, и это тоже отмечено предупреждением.
* **Выручка** = продано × цена. **Валовая прибыль** = продано × прибыль на единицу.
* **Чистая прибыль** = валовая прибыль − фулфилмент − ФОТ и сервисы.
* **Расходы (нагрузка)** берутся с листа ОПиУ как всё, что отделяет валовую прибыль по артикулам от чистой прибыли отчёта: ФОТ, налоги и пошлины, налоги кроме зарплатных, НДС, прочие расходы. Формула по каждому отчёту: Σ(продажи × прибыль на единицу по всем артикулам) − «Чистая прибыль» ОПиУ − «Выплата процентов по кредитным обязательствам» − «Услуги Фулфилмента». **Проценты по кредитам не относятся к инвестору и в нагрузку не входят**, фулфилмент считается отдельной строкой. Нагрузка делится на «Реализацию до СПП» за тот же месяц, при нескольких отчётах считается общий процент: Σнагрузки ÷ Σреализации. Месяц ищется по названию, строки по тексту, поэтому сдвиг строк не ломает расчёт.
* **Страховка**: если выручка по артикулам отличается от «Реализации до СПП» в ОПиУ больше чем на 25% (например, недели на листе артикулов заданы не на тот месяц), полная нагрузка не используется. Тогда расходы считаются только по ФОТ, внешней логистике, сервисам и сертификации, а в загрузке показывается предупреждение. Старые расчёты без чистой прибыли в сохранённых данных считаются так же; чтобы пересчитать их по новой формуле, загрузите отчёты заново («Добавить или заменить отчёты»).
* **Остаток** списывается по порядку закупок (сначала самые ранние партии); «в пути» в продажи не идёт.
* **Себестоимость проданного** = последняя известная себестоимость товара × продано.
* **Корректировка закупа** = (старая − новая себестоимость) × количество в партии.
* **Сальдо** = входящее + себестоимость проданного + чистая прибыль − потери − закупки ± корректировки + внесение − вывод.
* **Прибыль накопленным итогом** = сумма чистой прибыли всех месяцев.

## Сохранность данных и резервные копии

* Каждое сохранение на сайте — отдельный коммит в `investor-data` с понятным описанием. История файлов видна на github.com (раздел History у файла), любую правку можно откатить.
* Если запись на GitHub не удалась, сайт возвращает прежнее состояние и показывает ошибку, поэтому на экране не остаётся данных, которых нет в хранилище.
* Это резерв внутри того же аккаунта GitHub. От удаления репозитория или потери доступа он не защищает.
* Поэтому в «Справочнике» есть **«Скачать резервную копию»**: один JSON-файл со всеми данными. Скачивайте его после закрытия каждого месяца и храните вне GitHub (компьютер, облачный диск). Кнопка **«Восстановить из файла»** (только владелец) возвращает данные из такой копии; она ничего не удаляет.

## Вход инвестора по логину и паролю

Инвестору не нужен аккаунт GitHub. Владелец создаёт для него **отдельный токен** (fine-grained, только репозиторий `investor-data`, Contents: Read and write) и на вкладке «Справочник» в карточке «Доступ для инвестора» вводит логин, пароль (от 8 символов), владельца и имя репозитория данных, токен. Сайт шифрует подключение паролем (PBKDF2-SHA256, 600 000 итераций + AES-GCM) и скачивает файл `access.json`. Его нужно загрузить в корень репозитория сайта `report_invest` (Add file → Upload files). После этого при открытии сайта без подключения показывается окно входа; верный логин и пароль расшифровывают подключение прямо в браузере, роль устанавливается «инвестор». Кнопка «Выйти» удаляет токен с устройства.

Что важно: файл `access.json` публичный, поэтому пароль должен быть длинным (лучше фраза из нескольких слов) — слабый пароль можно подобрать перебором. Роль «инвестор» ограничивает только интерфейс: технически токен имеет право записи в репозиторий данных. Токены fine-grained живут не дольше года — перед окончанием срока создайте новый и пересоздайте `access.json`. Чтобы сменить пароль, создайте файл заново и загрузите поверх старого.

## Загрузка данных из сервиса оцифровки

Вместо Excel-отчётов можно брать данные из своего сервиса. Сервис (на сервере, не на сайте) раз в сутки записывает файл `import/ГГГГ-ММ.json` в приватный репозиторий `investor-data` (токен с правом записи только в этот репозиторий хранится на сервере сервиса). Сайт ничего не обращается к сервису напрямую. В окне «Создать расчёт» владелец выбирает месяц и нажимает «Загрузить из сервиса»: данные появляются в превью так же, как Excel-отчёты (предупреждения, проценты расходов), и сохраняются кнопкой «Создать расчёт». Excel остаётся запасным вариантом. Повторная загрузка заменяет данные тех же кабинетов. Если в месяце уже есть отчёты из Excel, окно предложит заменить их данными сервиса (галочка включена по умолчанию), иначе кабинеты сложились бы и продажи удвоились. Данные с `final: false` помечаются на странице месяца как «предварительно». Отрицательные органические продажи товара за месяц (самовыкуп попал в другой месяц) считаются как 0 проданных штук.

Формат файла `import/ГГГГ-ММ.json` (период — полный календарный месяц):

```json
{ "month": "2026-09", "generated_at": "2026-10-11T05:00:00Z", "final": true,
  "cabinets": [ { "marketplace": "wb | ym | ozon", "cabinet": "стабильное имя кабинета",
    "opiu": { "realization": 0, "net_profit": 0, "fot": 0, "fulfillment": 0, "interest": 0 },
    "articles": [ { "article": "артикул продавца", "organic_qty": 0, "avg_price": 0, "profit_per_unit": 0 } ] } ] }
```

Правила: `article` совпадает с «Артикулом продавца» в Excel-отчётах (по нему работает справочник); `organic_qty` — продажи минус самовыкупы; `avg_price` — средняя цена продажи до СПП; `profit_per_unit` — прибыль на единицу; строки «Без артикула» не включаются (или получают артикул `-1`, сайт их пропускает); в `opiu` расходы (`fot`, `fulfillment`, `interest`) можно передавать любым знаком, сайт берёт модуль, `net_profit` передаётся со знаком; `final: true` ставится, когда месяц закрыт (после 10-го числа следующего месяца), до этого сайт показывает предупреждение. Расходы инвестора считаются так же, как для Excel (полная нагрузка без процентов по кредитам). Размер файла — до 1 МБ (ограничение GitHub API).

## Важно знать

* Роли («владелец» и «инвестор») ограничивают только интерфейс. Токен инвестора технически даёт доступ ко всему репозиторию данных. Это нормально для доверительного учёта, но не защита от злого умысла.
* Токен хранится в браузере устройства. Не вводите его на чужих компьютерах; в диалоге можно отключить «Запомнить токен».
* Если владелец и инвестор одновременно правят одни и те же данные, побеждает последнее сохранение. Внесение и вывод средств лежат в отдельном файле, поэтому они не затираются при работе владельца. После чужих правок нажмите **Обновить**.
* Артикулы, которых нет в справочнике (аксессуары и прочее), в расчёт не попадают. Для Яндекс Маркета и Ozon заранее сопоставлены только однозначные названия, остальные (например, краскопульты и споттеры) нужно сопоставить вручную.
* Локальный режим («проба») хранит данные только в этом браузере. Они пропадут при очистке данных сайта.
