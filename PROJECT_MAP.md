## 1. Как устроен проект целиком

Проект состоит из двух репозиториев на GitHub:

- **`report_invest`** — публичный репозиторий с кодом сайта. Здесь только файлы сайта (`index.html`, `js/`, `css/`), никаких данных и цифр. Сайт размещён на GitHub Pages и открывается по адресу `https://ВАШ-ЛОГИН.github.io/report_invest/`. Публичным он сделан потому, что Pages для приватных репозиториев работает только на платных тарифах; без токена сайт показывает пустой интерфейс, так что посторонний ничего не увидит.
- **`investor-data`** — приватный репозиторий с данными. Все цифры (продажи, закупки, сальдо, внесения и выводы) хранятся здесь в виде JSON-файлов. Сайт читает и записывает их через GitHub API.

**Как обновляется.** Каждое сохранение на сайте — это отдельный коммит в репозиторий данных с понятным описанием. Вся история изменений видна на github.com (кнопка History у файла), любую правку можно откатить. Если запись на GitHub не удалась, сайт возвращает прежнее состояние и показывает ошибку — на экране не остаётся данных, которых нет в хранилище.

**Роли.** Есть две роли: «Владелец» (вы) и «Инвестор». Роль ограничивает только интерфейс: инвестор не видит лишних кнопок, но технически его токен имеет право записи в репозиторий данных. Это нормально для доверительного учёта, но не защита от злого умысла.

**Отчёты.** Excel-отчёты маркетплейсов читаются прямо в браузере (только нужные листы, поэтому файлы по 5–9 МБ открываются быстро). Сами файлы никуда не загружаются — в базу попадают только строки по артикулам и суммы расходов. Поддерживаются отчёты WB (листы «По артикулам» и «ОПиУ - месяцы»), Яндекс Маркета («По Артикулам» и «ОПиУ - месяцы») и Ozon («Артикулы» и «ОПиУ»). Кабинет определяется по полю «Юрлицо» на листе «Информационный лист».

**Запасной канал данных.** Вместо Excel можно брать данные из своего сервиса оцифровки: сервис раз в сутки записывает файл `import/ГГГГ-ММ.json` в репозиторий данных, а сайт забирает его кнопкой «Загрузить из сервиса». Excel остаётся запасным вариантом.

| Файл | Что хранит | Кто меняет |
|---|---|---|
| `settings.json` | Справочник «артикул WB → товар инвестора», входящее сальдо первого месяца, прибыль накопленным итогом до начала учёта, доля инвестора по умолчанию (1/3) | Владелец, через вкладку «Справочник» |
| `ledger.json` | Закупки (партии товара), потери товара, корректировки себестоимости | Владелец, через вкладку «Товар инвестора» |
| `flows.json` | Внесение и вывод средств по месяцам | Владелец и инвестор, через вкладку «Движение денег» |

## 4. Вкладки и кнопки интерфейса

### Подключение

Настраивается отдельно на каждом устройстве. Поля: источник (GitHub), логин владельца репозитория, имя репозитория данных, ветка (`main`), токен, роль (владелец/инвестор). Кнопка **«Проверить»** проверяет связь, **«Сохранить»** запоминает подключение. Галочка «Запомнить токен» хранит токен в браузере — на чужих компьютерах её лучше снимать. Если сайт открыт без подключения и в репозитории есть `access.json`, показывается окно входа по логину и паролю (это вход для инвестора). Кнопка **«Выйти»** удаляет токен с устройства. Есть локальный режим «проба» — данные хранятся только в браузере и пропадут при очистке данных сайта.

### Расчёт за месяц

- **«Создать расчёт»** — выбираете месяц и перетаскиваете Excel-отчёты всех кабинетов (можно все сразу). Новый файл того же кабинета заменяет прежний, остальные остаются — так можно добавлять кабинеты по одному.
- **«Загрузить из сервиса»** — то же самое, но данные берутся из файла сервиса оцифровки. Если в месяце уже есть отчёты из Excel, окно предложит заменить их (галочка включена по умолчанию) — иначе кабинеты сложатся и продажи удвоятся.
- **«Пересчитать»** — пересчитывает месяц после изменений (новые закупки, потери, сопоставление артикулов, другая доля инвестора).
- **«Добавить или заменить отчёты»** — загружает отчёты заново, чтобы пересчитать старые месяцы по новой формуле.

На странице месяца видны предупреждения: продажи товара, которого нет на складе; отсечение проданного сверх остатка; срабатывание «страховки» по расходам; пометка «предварительно» для данных сервиса с `final: false`. Блок «Как получены средние цена и прибыль на единицу» показывает, из чего сложилась каждая средняя.

### Товар инвестора

Деньги в товаре: на складе и в пути. Кнопка **«Новая закупка»** добавляет партию: товар, себестоимость, количество, месяц, статус. Галочка **«Начальный остаток»** — для товара, который уже был на складе до начала учёта: деньги за такие партии не списываются (они уже учтены во входящем сальдо). Товар «в пути» переводится «на склад» выпадающим списком «Статус» в строке партии (только у владельца). Здесь же вносятся потери товара и корректировки себестоимости.

### Движение денег

Таблица как в Excel: месяцы в столбцах, статьи в строках. Входящий остаток, проданный товар, чистая прибыль, сгоревший товар, новые закупки, корректировки и накопленная чистая прибыль подтягиваются автоматически. Вручную вводятся только **внесение** и **вывод средств** — это может делать и инвестор. После чужих правок нажмите **«Обновить»**.

### Справочник

- **Соответствие «артикул WB → товар инвестора»** — главная таблица привязки. Список «без привязки» показывает артикулы с продажами и маркетплейс, по которым товар ещё не выбран. Артикулы, которых нет в справочнике, в расчёт не попадают.
- **Параметры** — «Входящее сальдо первого месяца» и «Прибыль накопленным итогом до первого месяца» (остатки на дату начала учёта), доля инвестора по умолчанию.
- **Доступ для инвестора** — создание файла `access.json` для входа по логину и паролю (см. раздел 5).
- **«Скачать резервную копию»** — один JSON-файл со всеми данными. Скачивайте после закрытия каждого месяца и храните вне GitHub.
- **«Восстановить из файла»** (только владелец) — возвращает данные из резервной копии, ничего не удаляя.

## 5. Где лежат настройки, ключи, пароли и резервные копии

- **Токен владельца** — GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens. Доступ: только репозиторий `investor-data`, право Contents: Read and write. Хранится в браузере вашего устройства.
- **Токен инвестора** — создаётся отдельно тем же способом, чтобы его можно было отозвать, не трогая свой. Передаётся инвестору лично или зашивается в `access.json`.
- **Логин и пароль инвестора** — задаются на вкладке «Справочник» в карточке «Доступ для инвестора» (пароль от 8 символов, лучше фраза из нескольких слов: файл `access.json` публичный, слабый пароль можно подобрать перебором). Сайт шифрует подключение паролем (PBKDF2-SHA256, 600 000 итераций + AES-GCM) и скачивает `access.json` — его нужно загрузить в корень репозитория `report_invest` через Add file → Upload files.
- **Срок жизни токенов** — fine-grained токены живут не дольше года. Перед окончанием срока создайте новый токен и пересоздайте `access.json`. Чтобы сменить пароль инвестора, создайте файл заново и загрузите поверх старого.
- **Настройки расчёта** (доля инвестора, входящее сальдо, прибыль до начала учёта) — в файле `settings.json`, меняются через вкладку «Справочник». В коде эти числа не хранятся.
- **Резервные копии** — кнопка «Скачать резервную копию» в «Справочнике». Коммиты в GitHub — это резерв внутри одного аккаунта: от удаления репозитория или потери доступа он не защищает. Поэтому файл-копию храните на компьютере или в облаке.

## 6. Как считается прибыль — все формулы

**Продано.** Доля инвестора (по умолчанию 1/3, меняется в «Справочнике» и отдельно для месяца при пересчёте) умножается на органические продажи по всем отчётам, результат округляется вверх. Продажи учитываются только по товарам, которые есть у инвестора на складе (с учётом начальных остатков и закупок «на складе»). Товар «в пути» не продаётся. Продано не может быть больше остатка на складе — избыток отсекается с предупреждением. Отрицательные органические продажи за месяц считаются как 0 штук.

**Средняя цена и средняя прибыль на единицу.** Считаются по всем кабинетам и маркетплейсам вместе: сумма (значение × продажи) делится на сумму продаж. Учитываются только артикулы с положительными продажами. Берутся «средний чек / цена продажи до СПП» и «операционная прибыль на единицу». Из чего сложилась каждая средняя, видно на странице месяца в блоке «Как получены средние цена и прибыль на единицу».

**Выручка и валовая прибыль.** Выручка = продано × средняя цена. Валовая прибыль = продано × средняя прибыль на единицу.

**Расходы (нагрузка).** Берутся с листа ОПиУ как всё, что отделяет валовую прибыль по артикулам от чистой прибыли отчёта: ФОТ, налоги и пошлины, налоги кроме зарплатных, НДС, прочие расходы. Формула по каждому отчёту:

> Нагрузка = Σ(продажи × прибыль на единицу по всем артикулам) − «Чистая прибыль» ОПиУ − «Выплата процентов по кредитным обязательствам» − «Услуги Фулфилмента»

Проценты по кредитам к инвестору не относятся и в нагрузку не входят, фулфилмент считается отдельной строкой. Нагрузка делится на «Реализацию до СПП» за тот же месяц; при нескольких отчётах считается общий процент: сумма нагрузок ÷ сумма реализаций. Месяц в отчёте ищется по названию, строки — по тексту, поэтому сдвиг строк в Excel не ломает расчёт.

**Страховка.** Если выручка по артикулам отличается от «Реализации до СПП» в ОПиУ больше чем на 25% (например, недели на листе артикулов заданы не на тот месяц), полная нагрузка не используется: расходы считаются только по ФОТ, внешней логистике, сервисам и сертификации, а в загрузке показывается предупреждение. Старые расчёты без чистой прибыли в сохранённых данных считаются так же; чтобы пересчитать их по новой формуле, загрузите отчёты заново кнопкой «Добавить или заменить отчёты».

**Чистая прибыль** = валовая прибыль − фулфилмент − ФОТ и сервисы.

**Остаток и себестоимость.** Остаток товара списывается по порядку закупок: сначала самые ранние партии (FIFO). Себестоимость проданного = последняя известная себестоимость товара × продано.

**Корректировка закупа** = (старая себестоимость − новая себестоимость) × количество в партии.

**Сальдо месяца** = входящее сальдо + себестоимость проданного + чистая прибыль − потери − закупки ± корректировки + внесение − вывод.

**Прибыль накопленным итогом** = сумма чистой прибыли всех месяцев (плюс историческая прибыль до начала учёта, заданная в параметрах «Справочника»).

## 7. Как проверить расчёт: три готовых примера

Эти примеры можно посчитать на калькуляторе и сверить с тем, что показывает сайт (или что насчитал Claude Code после правок). Если цифры не сходятся — расчёт сломан.

### Пример 1. Продано, средние цена и прибыль, выручка

Условие: органические продажи товара за месяц — 100 шт, доля инвестора 1/3. Продажи были в двух кабинетах:

- кабинет 1: 60 шт, цена 1000 ₽, прибыль на единицу 300 ₽;
- кабинет 2: 40 шт, цена 1200 ₽, прибыль на единицу 360 ₽.

Проверка:

1. Продано = 100 ÷ 3 = 33,33… → округление вверх → **34 шт**.
2. Средняя цена = (60 × 1000 + 40 × 1200) ÷ 100 = 108 000 ÷ 100 = **1080 ₽**.
3. Средняя прибыль на единицу = (60 × 300 + 40 × 360) ÷ 100 = 32 400 ÷ 100 = **324 ₽**.
4. Выручка = 34 × 1080 = **36 720 ₽**.
5. Валовая прибыль = 34 × 324 = **11 016 ₽**.

### Пример 2. Нагрузка (расходы) и проценты по кредитам

Условие по одному отчёту: сумма (продажи × прибыль на единицу) по всем артикулам = 500 000 ₽; чистая прибыль в ОПиУ = 300 000 ₽; выплата процентов по кредитам = 20 000 ₽; услуги фулфилмента = 50 000 ₽; реализация до СПП = 1 000 000 ₽.

Проверка:

1. Нагрузка = 500 000 − 300 000 − 20 000 − 50 000 = **130 000 ₽**. Обратите внимание: проценты по кредитам вычитаются из нагрузки, то есть инвестор их не оплачивает.
2. Процент нагрузки = 130 000 ÷ 1 000 000 = **13%**.

### Пример 3. Сальдо месяца

Условие: входящее сальдо 1 000 000 ₽; себестоимость проданного товара 200 000 ₽; чистая прибыль 150 000 ₽; потери товара 10 000 ₽; новые закупки 100 000 ₽; корректировка себестоимости +5 000 ₽; внесение средств 0 ₽; вывод средств 50 000 ₽.

Проверка:

Сальдо = 1 000 000 + 200 000 + 150 000 − 10 000 − 100 000 + 5 000 + 0 − 50 000 = **1 195 000 ₽**.

## 8. Типичные сценарии работы

### Новый месяц (обычный порядок)

1. В каждом Excel-отчёте на листе «По артикулам» (у Ozon — «Артикулы») задайте недели месяца: неделя относится к месяцу, если в нём хотя бы 4 её дня.
2. Нажмите **«Создать расчёт»**, выберите месяц и перетащите все файлы отчётов. Кабинеты можно добавлять по одному: новый файл того же кабинета заменяет прежний, остальные остаются.
3. Если были новые закупки, потери или изменилась себестоимость — внесите на вкладке **«Товар инвестора»**.
4. Если появились артикулы «без привязки» — сопоставьте их товарам на вкладке **«Справочник»**, затем нажмите **«Пересчитать»** в нужном месяце.
5. Инвестор отмечает внесение и вывод средств на вкладке **«Движение денег»**.
6. Проверьте исходящее сальдо и прибыль накопленным итогом.
7. Скачайте резервную копию («Справочник» → «Скачать резервную копию») и сохраните её вне GitHub.

### Изменение доли инвестора (или других настроек)

Доля по умолчанию меняется на вкладке **«Справочник»** (сохраняется в `settings.json`). Для конкретного месяца долю можно изменить отдельно при пересчёте. В коде сайта доля не хранится — трогать файлы не нужно. После изменения пересчитайте затронутые месяцы кнопкой «Пересчитать».

### Перенос на другой компьютер

Подключение настраивается на каждом устройстве отдельно. На новом компьютере: откройте сайт → «Подключение» → укажите логин владельца, репозиторий `investor-data`, ветку `main`, вставьте ваш токен, выберите роль «Владелец» → «Проверить» → «Сохранить». Никаких файлов переносить не нужно — все данные в репозитории на GitHub.

### Восстановление из резервной копии

«Справочник» → «Восстановить из файла» (только владелец) → выберите скачанный ранее JSON-файл. Восстановление ничего не удаляет: оно добавляет данные из копии новым коммитом.

### Продление токена или смена пароля инвестора

Токены fine-grained живут не дольше года. Перед окончанием срока создайте новый токен (GitHub → Settings → Developer settings → Personal access tokens), обновите подключение у себя и пересоздайте `access.json` для инвестора («Справочник» → «Доступ для инвестора»), затем загрузите новый файл поверх старого в корень `report_invest`. Тем же способом меняется пароль инвестора.

## 9. Важные ограничения, о которых нужно помнить

- **Роли — только в интерфейсе.** Токен инвестора технически даёт доступ на запись ко всему репозиторию данных. Это нормально для доверительного учёта, но не защита от злого умысла.
- **Токен хранится в браузере.** Не вводите его на чужих компьютерах; в диалоге подключения можно отключить «Запомнить токен».
- **Одновременные правки.** Если владелец и инвестор правят одни и те же данные одновременно, побеждает последнее сохранение. Внесение и вывод средств лежат в отдельном файле `flows.json`, поэтому они не затираются при работе владельца. После чужих правок нажмите «Обновить».
- **Артикулы без привязки не считаются.** Артикулов, которых нет в справочнике (аксессуары и прочее), в расчёт не попадают. Для Яндекс Маркета и Ozon заранее сопоставлены только однозначные названия; остальные (например, краскопульты и споттеры) нужно сопоставить вручную.
- **Файл `access.json` публичный.** Пароль инвестора должен быть длинным — лучше фраза из нескольких слов; слабый пароль можно подобрать перебором.
- **Локальный режим «проба»** хранит данные только в этом браузере. Они пропадут при очистке данных сайта.
- **Резерв внутри GitHub — не полная защита.** История коммитов спасает от ошибочных правок, но не от удаления репозитория или потери доступа к аккаунту. Поэтому скачивайте резервную копию после закрытия каждого месяца и храните её на компьютере или в облаке.
